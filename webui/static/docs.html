What this is

SortIQ is the brain of an automatic brass-sorting machine. It looks at the head of a fired case through a camera, reads the headstamp (the maker's marking, like WIN or FC), and drops the case into the matching bin. Anything it isn't sure about goes to the UNMATCHED bin — the machine would rather make you re-run a case than put it in the wrong bin.

PartJobWhere it runs
This software (Python)Camera, AI models, decisions, this web pageThe machine's Raspberry Pi (and any PC, for training or development)
CS7.2 board (Arduino Uno, TMC2209 drivers)Motors, sensors, light ring, timingOn the machine, over USB serial — stock firmware or the SortIQ fork; a faithful simulator stands in when no board is connected
MechanicsHopper, feed wheel, imaging nest, sorter arm, binsSeth Hahner's CS7.2 design

Crimp detection (sorting crimped vs non-crimped primer pockets) was part of an earlier design and has been retired for now — flat lighting and webcam resolution couldn't resolve it reliably. Sorting is by headstamp only: one bin per headstamp, plus unmatched.

How a case gets sorted

1 · Photo One photo of the case head, framed by the live crop preview.
↓
2 · Quality gate The photo must be sharp enough. A blurry photo is rejected before the AI ever sees it — better no guess than a bad guess.
↓
3 · Embedding match A neural network turns the headstamp crop into a compact fingerprint vector, then compares it against a gallery of exemplar photos — a handful of representative images per headstamp, picked automatically for coverage (you can pin or exclude any on the Dataset page). The closest class wins, with a similarity score.
↓
4 · Three honesty gates The match must clear that class's own bar (each class earns its bar from how tightly its exemplars agree), and it must be clearly ahead of the runner-up — a near-tie between look-alikes is rejected as "too close to call" rather than coin-flipped. The case is also read at four rotations; disagreement is logged as a warning sign.
↓
5 · Bin All gates pass → the stamp's bin. Anything less → UNMATCHED, with a plain-language reason ("Too close to call — SPEER 91% vs BLAZER 89%").

Why matching beats guessing

Older designs used a classifier that had to pick one of the classes it was trained on — a stamp it had never seen would still come out as somebody's name, often confidently. The embedding+gallery design is open-set: a stranger doesn't resemble anyone's exemplars strongly enough to clear the gates, so it lands in UNMATCHED instead of a bin. And adding a new headstamp needs no retraining — file 3+ photos and the gallery starts matching it immediately.

The rejection philosophy

  • Rejected (sent to UNMATCHED): costs you one re-run of that case. Cheap.
  • Misfiled (wrong bin): silently contaminates a bin. Expensive.

Every threshold exists to trade reject-rate for misfile-rate. When in doubt, the machine rejects. Your target is a misfile rate of zero at whatever reject rate that costs.

The Machine tab is a live console for this protocol: connect to the real board (or the simulator), press the quick-command buttons or type raw lines, and watch both directions of traffic. Growing the dataset — doing it right

Headstamps and photos are managed on the Collect and Dataset tabs; the Sort page assigns each physical bin a headstamp (exactly one bin is UNMATCHED, and unassigned headstamps route there too). A class is live in the gallery — and therefore sortable — from 3 photos; it joins the periodic training pass (which sharpens the whole network) at 10+.

Rule 1 — photograph like the machine will see

  • Fix the camera, the case position, and the lighting, and never touch them again mid-dataset.
  • Judge quality in the live crop preview: if you can read the stamp easily, the model can learn it. Dark, etched-looking letters on bright metal beat washed-out glare every time.
  • Diffuse the light for reflective nickel cases — point light creates glare that burns out exactly the letters you need.

Rule 2 — quantity targets

Class sizeWhat it means
1–2 photosthe class exists, waiting for siblings ("needs 3+ to enter the gallery")
3–9 photoslive in the gallery — sortable today, skipped by the training pass
10–300full citizen: gallery + training
300+saves are skipped only when pixel-verified as the same physical case already filed (matching scratch pattern at some rotation — re-run brass); distinct cases always file, however alike the stamp looks
500+well-fed: batch filing switches from volume to variety — File novel keeps only photos showing the class a genuinely new look and skips routine near-identicals (File all overrides). Hard cases (the "Looks like X" and unknown piles) always file in full — they teach the most.

The Dataset and Train class lists color-code these tiers: red under 10, plain 10–299, amber 300+, green 500+ — sort the list by count and the red tail is your re-photo shopping list.

Two ways to collect: the chained capture loop (Collect tab — feed, photograph, one keypress per case, with the model pre-selecting labels) and batch capture (run the whole hopper at machine speed, then confirm grouped cards — whole groups file with one click, and any case can be removed from its group first). Variety beats volume — many different physical cases (worn, tarnished, shiny) beat many shots of one case.

Rule 3 — unknown is a state, not a category

When a stamp you don't recognize shows up (in a reject review or the capture flow), choose Set aside — identify later. Set-aside photos land in the tray at the top of the Dataset page, clustered by similarity so five copies of the same mystery stamp arrive as one group. Name the group (the community headstamp list below is the naming cheat sheet) and every photo files at once — the class is created and, at 3+ photos, starts sorting immediately. The tray exists to be emptied.

Class structure — split for the model, family for the bin

The matcher identifies by look, not brand. When one headstamp name covers visibly different dies (FC plain / dots / diamonds, WIN plain / numbers / +P), give each look its own class — a variant hiding inside its parent matches at coin-flip margins, while a split class matches decisively. Then group the variants into a family (Dataset page) and assign the family to a bin: they sort together physically, and a close call between two family members headed to the same bin is accepted instead of rejected — hesitating between siblings costs nothing. Keep classes honest with the mislabel scan (seconds, whole dataset) and re-scan after fixes. The full doctrine: docs/TRAINING_GUIDE.md.

Training

  • The gallery handles day-to-day growth with no training at all — new classes, new photos, pins and exclusions all take effect at the next Rebuild gallery — seconds, on either machine (unchanged photos reuse their stored vectors; only a fresh model pays full price once).
  • A full retraining of the embedding network sharpens everything — worth doing after the dataset has grown or shifted substantially. On the machine, Train models… (Train tab) opens a window that drives the trainer on the PC you're browsing from — sync, device choice, progress, result, install, all without leaving this page. Pick GPU (about an hour) or CPU (overnight — the trainer stays usable) and press Start. The result is staged as a candidate with its bench numbers; nothing replaces the live model until you press Install, which archives the current generation (restorable from the Train page) and pushes the new model + gallery pair to the machine. If the GPU fails, the app asks whether to retry it or train on CPU — it never switches by itself.
  • After moving/deleting images or changing the crop geometry: Rebuild crops, then Rebuild gallery.

The gates

GateWhat it doesWhere it comes from
Sharpness floorMinimum photo crispness; catches bumped cameras and mid-drop shotsrig-specific, set in the profile
Class barThe match must be at least this similar to the class's exemplarsearned per class from how tightly its exemplars agree (floor 85%); the Sort page's Acceptance slider shifts every bar together — 85% is neutral, higher is stricter
Runner-up marginThe winner must clearly beat the second-best class — near-ties reject as "too close to call"fixed small gap (3%)

The bars tune themselves from the gallery — the practical lever is the dataset. Lots of correct-but-rejected cases of one stamp → more photos of it (especially the looks it rejects on), then rebuild the gallery. A misfiled case → find it in the run report, refile it to the right class, and check that class for mislabeled images (Scan for mislabels).

Testing & validation

  • Test tab: classify from the live camera, an upload, or a synthetic case. Every gate shows its measured value, the bars show the closest gallery matches (winner and runner-up with their similarities), and the disc shows the destination bin. A reject explains itself in plain language.
  • Test → Add to training data: when the model gets one wrong, correct the label and save it — the images it struggles with are the most valuable training data there is. The Test tab is also the mislabel detective: if a known case matches the wrong class, the runner-up trail usually leads to a mislabeled image sitting in that class's folder.
  • Sort tab: full sorting runs (simulator or hardware) with a live feed, per-bin counts, throughput, and a ground-truth scorecard in sim mode: correct / rejected / misfiled. Misfiled is the number to drive to zero. Every case's photo is kept for the run report, so any card can be reassigned or filed into the dataset afterwards.

Moving to the Pi

Getting the Pi online

  1. First boot — set Wi-Fi before flashing. In the Raspberry Pi Imager, use the settings gear when writing the SD card: set the hostname (pisortiq), enable SSH, and enter your Wi-Fi SSID and password. The Pi joins your network on its very first boot — no monitor or keyboard needed. Then browse to http://pisortiq.local:5000 — or, from the trainer's Train page, click Find machine… to scan the network (works even when .local names don't resolve).
  2. Ethernet always works — plug in and the Pi gets an address via DHCP alongside (or instead of) Wi-Fi.
  3. Changing Wi-Fi later: click the network readout in the page header (top right) — it shows every interface with its address, scans for nearby networks, and joins or forgets them (it drives NetworkManager, standard on Raspberry Pi OS). Joining a new network drops the old one, so do it while connected over ethernet when you can.
  4. Optional, for a machine that travels: an access-point fallback (the Pi opens its own SortIQ-Setup hotspot when it can't find a known network) can be added with the Debian comitup package — an OS-level install, independent of this app.

More than one machine

Every machine answers at <its-hostname>.local:5000 — hostnames are set at flash time and must be unique (two Pis sharing one makes the name flip between them). Click the name in the page header to label each machine ("9mm Master"); the label shows in the header, tab title, and the trainer's Find machine… list. The load-bearing rule: give each machine's model a unique name (9mm/Master, 9mm/Secondary) — the trainer files its dataset mirrors by caliber/model, and it will refuse to pull two different machines into one mirror. Full fleet guidance: docs/USER_MANUAL.md.

Installing the app

One command from your workstation does the whole install (rsync + venv + inference stack + a boot service), and re-running it later ships updates without touching the Pi's settings or collected images: 

tools/pi_deploy.sh          # defaults to pisortiq@pisortiq.local

The full walkthrough — flashing, deploying, and the first-connect bring-up checklist — is in docs/PI_SETUP.md. Models and config come along unchanged (nothing is retrained), and training stays on the PC: collect on the Pi, export the dataset backup, train, redeploy.

Troubleshooting

SymptomLikely cause → fix
“no embedding model installed” when starting a run or testingThe machine needs a model + gallery pair from the trainer → install one from the trainer's Train page
Everything goes to UNMATCHED (below its class bar)Photos don't match dataset conditions (camera moved, lighting changed) or the classes involved are thin → more photos on the same rig, then Rebuild gallery; check the crop under “what the model saw”
Everything rejected as blurrySharpness floor set above what the camera delivers → check the live sharpness readout, lower the floor. The light ring is powered by the sorter board — board off = dark, low readings.
The green circle misses the caseBusy background confusing rim detection → plain dark background, case filling more of the frame
Wrong stamp in a binThe one unacceptable fault, and almost always a data problem → refile the case from the run report, then run Scan for mislabels on both classes involved (a mislabeled image that became an exemplar attracts its real class), fix, Rebuild gallery
Two stamps keep rejecting as “too close to call”Honest behavior for look-alikes → more photos of both (especially the looks it rejects on), Rebuild gallery; a full retrain sharpens the pair further
Mislabeled or bad training imageDataset tab → View → click the thumbnail: review full-size, Move to the right class, or Delete. Moves are instant — the crop travels with the photo.
Suspect there are mislabels you haven't spottedDataset tab → Scan for mislabels: the decider re-reads every stored image and flags the ones it would accept as a different class. Those flags are nearly always real — View, then Move, then Rebuild gallery. Scan after big collection sessions.
